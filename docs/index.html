— the principle SwitchIt! is built on

Seven steps, one report

Everything runs locally until you explicitly opt in to a live provider. The baseline is always your recorded history — never a guess about what the old provider did.

01

Capture

Import authorized traces — OTLP, JSONL, Langfuse exports, or Parquet — plus your app's prompts and tool schemas.

02

Normalize and protect

Link sessions, preserve original IDs, redact secrets at import. Token usage stays separated: recorded, estimated, unknown.

03

Map workflows

Group traces into provisional workflows with evidence and uncertainty flags. Correct the labels; the map keeps your edits.

04

Freeze the replay set

Pick cases covering common, costly, risky, and failed paths. Add explicit success checks — a historical response alone is not proof.

05

Replay both sides

The same cases through the recorded baseline and the target adapter. Proposed tool calls are captured, never executed.

06

Compare

Checks, tool behavior, latency, and usage — with honest verdicts. Uncertain is a first-class answer, not a hidden failure.

07

Report

A local HTML and JSON migration report: what passes, what breaks, what remains unknown, and the fixes in priority order.

↻

Fix, then replay

Change the adapter, the prompt, or the check. Re-run. Checkpoints resume; changed inputs are refused, not silently mixed.

Four verdicts, no lies

Every case ends in exactly one of four states. The report tells you why, quotes the evidence, and separates "the target changed" from "your check was wrong."

pass — checks met fail — required check failed error — provider errored uncertain — said so, with reasons

Six commands, editable between each

Every stage writes a file you can read and correct before the next one runs — or run it all at once with run.

the whole pipeline
$ switchit import --jsonl traces.jsonl \
    --app-config app_config.json
$ switchit profile
$ switchit map --keep-edits
$ switchit cases
$ switchit replay --target mock
$ switchit report
$ open .switchit/run/report.html
  • importBuilds the canonical store. Secrets are redacted here and never appear again — in files, reports, or replay.
  • profileDigs through the sessions: system prompts, tool inventory with schemas inferred from observed calls, provider mix, errors. Writes an editable app_config.
  • mapDrafts the workflow map. You correct names and members; --keep-edits preserves them on re-runs.
  • casesFreezes a small replay set with default checks. Edit the JSON to define what success actually means.
  • replayRecorded baseline vs target adapter, checkpointed after every case. --remote is the explicit opt-in to a live provider.
  • reportWrites report.json and a self-contained report.html. No server, no external assets, nothing leaves your machine.

Memory tools and SwitchIt! answer different questions

Supermemory is good at what it does. It is not this. One stores what your agent knows; the other verifies what your workflow does — and the second one is what a provider switch puts at risk.

Supermemory — "Will my agent remember?"

Stores and recalls context across sessions. It solves memory: the state your agent carries between conversations. Valuable, and a different job entirely.

SwitchIt! — "Will my agent still work?"

Replays your recorded traces against a candidate provider and reports what survives: checks, tool behavior, latency, usage. It solves portability: the workflow itself.

Why can't a memory vendor just add this? Their data model is memories, not traces — no telemetry importers, no wire adapters, no check semantics, no usage provenance. And their incentive is to become the lock-in; SwitchIt! exists to break it. Gateways route traffic and eval platforms score quality — neither treats your production traces as the migration contract.

Supermemory gives your agent memory. SwitchIt! proves your agent still works when you swap the brain underneath it.

The complement, not the competitor

SwitchIt! replaces nothing in your stack. It consumes what the rest of it already produces, and adds the one layer nobody else has: proof that a provider change is safe.

Observability — OTel, Langfuse, LangSmith, Braintrust They record what happened. SwitchIt! ingests those exports — OTLP, JSONL, Langfuse, Parquet — and turns the recordings into a replayable migration contract.
Gateways & routers — LiteLLM, OpenRouter, Portkey They flip traffic with a config change. SwitchIt! tells you whether to flip it: replay first, then let the gateway route.
Memory & state — Supermemory and friends They carry what your agent knows across sessions. Their tool calls are captured as evidence, and recorded fixtures let a chained replay complete memory-dependent workflows offline — without ever executing a real memory write.
Agent frameworks — LangChain, OpenAI SDK, Claude Agent SDK, CrewAI, Mastra Replay happens at the wire protocol, not the framework, so it works regardless of what your agent is built with.
CI & pipelines The recorded baseline and mock adapters run fully offline with zero credentials, so migration checks belong in your pipeline, not on someone's laptop.

What SwitchIt! will not claim

  • Workflow labels and similarity scores are triage aids, not measured accuracy.
  • Proposed tool calls are captured for comparison; the harness never executes a business tool.
  • A historical model response is reference behavior, not proof of success — checks define success explicitly.
  • Token usage is telemetry, not invoices: recorded, estimated, and unknown stay separated.
  • End-to-end outcomes stay unverified until a safe tool fixture or authorized test environment exists.
